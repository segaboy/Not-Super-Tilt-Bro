Already available and tested
----------------------------

The port project's cycle-aligned comparison runs neutral, player-one-only, player-two-only, and combined inputs to a common requested NES cycle. The witness confirms guest reads on both ports and set bits on the active ports. It does not identify the affected fighter or establish game fidelity.

The supplied NES ROM has SHA-256 5d045246f12d424c2c67ecda883c66d8d346f7b5396ed819ddb326f44dcb5aaa and identifies itself as Super Tilt Bro 2.6 beta 5. Its precise source revision is unknown. Do not claim it is the current upstream build or redistribute it.

The port's original Mac controls probe boots in BootHush and moves a placeholder figure between three positions. Eight checks verify key presses, releases, movement bounds, framebuffer pixels and replay. It is not a playable game or an implementation of Super Tilt Bro mechanics, and it has not been tested on physical hardware.

1. Per-frame and event-aligned capture
--------------------------------------

We need to see how a source-game action evolves over time, rather than compare only the final frame.

- Add bounded capture of multiple complete NES frames in one run at requested frame numbers, modeled cycles, or offsets from a supported readiness condition. Include frame number, requested and actual guest cycles, and input ordering in a manifest.
- Provide corresponding Mac captures at modeled VBL boundaries or clearly defined guest-cycle points, without a visible window.
- Allow selected CPU RAM observations and, where applicable, PPU/OAM or Mac framebuffer observations alongside captures at declared boundaries. Report which observations are simultaneous and which are not.
- Preserve existing capture options. Protect existing files, bound storage and event counts, and report missing captures, dropped events, truncation and early termination.
- Define ordering when a capture, input, readiness condition and stop condition coincide. Be explicit about instruction-boundary rounding and whether a screenshot is the last completed frame.

Acceptance: independent synthetic fixtures demonstrate repeated deterministic multi-frame capture, correctly ordered events, bounded output and negative/error cases. Apply the feature optionally to the pinned beta to capture a short neutral sequence and a single-controller movement sequence at comparable guest times. Do not label that result as physical accuracy or gameplay equivalence.

2. Mac keyboard and gameplay diagnostics
-----------------------------------------

The current Mac probe observes that presses and releases reached its own diagnostic RAM. We need to debug more complex held keys and simultaneous input.

- Add a bounded, opt-in witness correlating scheduled key transitions with the modeled M0110 queue, commands and replies, VIA shift-register activity, and guest consumption where observable.
- Record guest cycle and relevant instruction context. Report queue overflow, dropped records, trace truncation and unapplied input.
- Support reproducible multi-key holds, releases and overlapping transitions using the current model. Clearly distinguish emulator behavior from verified physical M0110 rollover and timing.
- Add useful opt-in Mac VBL, selected framebuffer-write and fault observations needed to debug animation and redraw cost, without requiring mouse-specific tracing.

Acceptance: original synthetic fixtures cover a press, hold, release, overlapping keys, queue limits and repeatability. Exercise the port's existing controls probe and prove that its scheduled releases are delivered to the guest. This is model evidence, not proof of physical-keyboard behavior.

3. Mac sound and synchronized capture
-------------------------------------

Implement the original Macintosh 128K sound behavior needed for an independently authored game ROM, using eligible hardware documentation and original implementation. Scope the first slice to what can be supported and tested; explicitly report unknown timing and fidelity.

- Allow headless capture with a documented sample format and guest-time relationship.
- Report underruns, overruns, dropped samples and truncation.
- Record enough timing information to align sound with Mac VBL/frame captures; improve NES audio/video alignment metadata where necessary for a comparison.

Acceptance: original fixture ROMs test silence, enable/disable and predictable tone or sample output; repeated captures are deterministic within declared model limits. State whether anyone listened. Synthetic waveform output alone is not evidence of hardware-faithful sound.

4. Inspect game state and execution
-----------------------------------

We need to understand movement, jumping, attacks, hitboxes, damage and stocks for a source version that can eventually be matched to a build.

- Add an opt-in, bounded NES witness for filtered instruction execution and selected memory and device reads/writes, with cycle, instruction context, mapper bank and interrupt context where available.
- Support named observations or project-provided symbol/address maps without hard-coding Super Tilt Bro data into the emulator.
- Record limits, dropped events, unsupported accesses and side effects. Do not silently infer data types or labels from addresses.

Acceptance: independently generated fixtures validate reads, writes, bank changes, filters, bounds, dropped-event reporting and repeatability. Demonstrate the workflow against the supplied beta only as an optional, hash-pinned observation. Its unknown revision means labels from the current source must not be assigned to it as fact.

5. Source-to-target comparison workflow
---------------------------------------

Create a small reusable vertical slice rather than a speculative universal framework.

- Define source and target profiles, ROM hashes, input scripts, guest readiness, capture points and emulator build identity.
- Allow a port project to map a logical action to NES controller input and Mac keyboard input, and to define named observations for each side.
- Compare selected outcomes and visual/audio event timing using explicit transformations, units, frame-rate mappings and tolerances. Retain raw observations.
- Clearly distinguish unsupported features, missing readiness, invalid images, guest faults, timeouts, dropped input and comparison failures.
- Demonstrate a simple movement scenario with original synthetic NES and Mac fixtures. Do not claim that the current placeholder Mac probe matches Super Tilt Bro.

Constraints and delivery
------------------------

- Use BootHush for all emulator runs. Keep automation headless and bounded; do not silently use another emulator, change ROM headers, substitute a larger Mac, or alter source media.

- Keep ROM images and generated captures out of Git. Use independent fixtures by default and retain source/license records for any third-party material.
- The missing usable 68000 compiler and version-matched NES build are port build-environment/source issues, not automatically BootHush features. Do not bypass environment restrictions to address them.
