# Provenance and boundaries

The Mac arena probe's reset and exception-vector relocation sequence is adapted
from ClasSICK 0.97 commit 5d99706, `arch/m68k/mac-reset.S`, copyright
Dean Howell, GPL-3.0-or-later. The generated arena and silhouettes are original
geometric test art. The probe includes no game assets, Apple ROM or System code.
The instruction bytes are emitted by a narrowly scoped Python builder; inspect
the generated bytes and run the automated BootHush checks before using them.

Super Tilt Bro source and the separately obtained author-provided 2.6 beta 5
NES image are observation inputs; the separately documented running-entry
slice translates a small part of the source behavior. No game assets are included.
That binary's exact source revision is unknown. Do not publish it as a fixture
without establishing rights and provenance. BootHush results are emulated
observations, not physical Mac or NES hardware measurements.

The three-position controls probe in scripts/build_mac_controls.py uses the
same adapted ClasSICK reset sequence and original geometric art, with original
input handling and instruction-emitter code. It is GPL-3.0-or-later. The NES
cycle-comparison script observes the separately supplied pinned beta image; it
does not include or distribute its code, graphics, or ROM.

The Sinbad PAL running-entry state transition in
`scripts/build_mac_run_transition.py` is a 68000 adaptation of behavior from
Super Tilt Bro commit `b132fd25add46f816e04be64c434386743b84b8b`, specifically
`game-mod/characters/sinbad/states.asm`, `game/templates/characters/std_running.asm`,
`game/templates/characters/std_idle.asm` and `game/macros.asm`. The source's
WTFPL v2 notice is retained in [the license copy](../third_party/super-tilt-bro-LICENSE.txt).
The adaptation also builds on the GPL-3.0-or-later controls probe and ClasSICK
reset sequence described above. See [the slice record](sinbad-running-slice.md)
for the exact scope and source-file hashes. The beta ROM is not established to
match this source, and its binaries and captures are not included in Git.

The later movement experiment adds source-derived Sinbad velocity and grounded
friction constants and movement-toward-target behavior from
`game/templates/characters/std_friction_routines.asm` and `game/logic/utils.asm`
at the same Super Tilt Bro revision. The generated arena, figure, input adapter,
frame pacing and bounds are original to this project. See
[movement evidence](movement-evidence.md) for the source hashes, limitations,
and distinction between emulator and hardware observations. Its startup still
uses the separately attributed GPL-3.0-or-later ClasSICK reset sequence.

The subsequent two-key bitmap and last-pressed direction policy are original to
this port and are not attributed to the source game or to historical Mac
keyboard behavior. They operate within the already attributed source-derived
movement experiment; see [overlap evidence](overlapping-direction-evidence.md).

The optional jump experiment adapts the jump-squat count, jump and short-hop
power magnitudes and the short-hop decision point from the same upstream game
revision. The input mapping, height-based coordinate representation, gravity
approximation, landing, tick integration and placeholder graphics are original
to this port. Exact source file identities and distinctions are recorded in
[jump evidence](jump-slice-evidence.md). Game-derived code and these observations
are not automatically eligible for ClasSICK implementation.

The optional jab experiment was informed by the first Sinbad jab state and
animation metadata at the same upstream revision, including a 24-count local
timeline and a two-point direct-hit value. Its attack pose, training target,
input and collision mapping, timing adaptation, damage storage and drawing
are original local choices. No upstream sprites or art are included. See
[jab evidence](jab-training-evidence.md) for exact source identities and
limitations; neither the game-derived input nor this ROM is a ClasSICK
implementation input.

The subsequent eight-cell visible damage indicator is original port artwork
and an original diagnostic presentation. It does not copy the game's damage
display or establish the source game's damage or stock mechanics.

The second-character experiment extends the attributed movement, jump and jab
slice. Its second player's constant-speed horizontal movement, input mapping,
simultaneous hit policy, bytewise composition and damage indicator are local
design choices. The second jump reuses the same source-informed constants and
local integration as the first. Its geometric figure is original to this port;
no upstream art is included. [Evidence](two-character-evidence.md). These
game-informed materials are not automatically eligible for ClasSICK.

The experimental mouse title's phase mapping and direction convention are
informed by the GPL-3.0-or-later ClasSICK 0.97 polled-phase research and the
hardware-alias hypothesis identified in [the title receipt](mouse-title-evidence.md).
The original title lettering, button, pointer, polling glue and handoff are
port-specific. They are not validated physical hardware behavior and should not
be transferred back to ClasSICK without its source-eligibility and independent
implementation process.

The later native-C diagnostic uses the same attributed source-informed running
and friction constants and the same previously credited startup sequence. Its
deterministic test harness and C translation are local port work; it is not
eligible as a ClasSICK implementation input. The Windows compiler is a separate
tool dependency with its own archive identity and unresolved licensing review.
See [native-C evidence](windows-native-c-evidence.md).

The later reusable C movement component retains the same source-informed
constants and attribution. Its two-direction test harness, arithmetic and
caller interface are local port work. It remains game-informed material and
is not eligible as a ClasSICK implementation input merely because BootHush
can execute it.

The later optional two-player C title reuses that same attributed movement
component for player two. Its per-player state, input bridge, attack lock and
tests are local adaptations. See [native-C evidence](windows-native-c-evidence.md)
for the exact build and distinctions; this remains game-informed port work.
